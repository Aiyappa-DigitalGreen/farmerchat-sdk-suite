FarmerChat SDK · Theming Guide · v1.0.0

How host apps override the FarmerChat look — one config, every screen.

The SDK ships a complete green-brand theme and recolors itself from a single FarmerChatConfig. This page documents every override layer that exists in the SDK today, the precedence rule that binds them, how each platform resolves them, and what is not yet overridable.

The one rule

Override resolution order

Every visual value the SDK draws is resolved through the same ladder. The first layer that is set wins; anything left unset falls through to the next. This is why an unset override always yields the SDK's current default — overrides are purely additive.

1
Per-instance parameter

Passed at a specific call site — e.g. FarmerChatFab(icon=…, containerColor=…). Highest precedence; scoped to that one widget.

↓ if not set
2
Config-level knob

Set once on FarmerChatConfig — the FAB defaults and the chat-UI knobs. Applies everywhere that widget/element appears.

↓ if not set
3
FarmerChatTheme token

The host brand theme on FarmerChatConfig.theme — brand colors, dark variants, corner radii, typography, logo. Recolors the whole journey.

↓ if not set
4
Built-in FarmerChat green

The shipped default palette/shape/type. What every host sees before overriding anything.

Text is a separate track. User-visible strings are not part of the color theme — they resolve through stringOverrides → server label ${key}_${lang} → ${key}_en → built-in English → raw key. See §5.

Layer 3 · the base theme

FarmerChatTheme — recolor the whole journey

Supplied via FarmerChatConfig.theme. Every field is optional; an omitted field keeps the built-in green value. A single resolver per platform overlays these onto the internal token layer, so every screen recolors with zero per-screen edits.

Layer 1 · per-instance FAB overrides

The launcher also takes call-site params that beat the config defaults: question, label, a custom icon (Compose ImageVector, SwiftUI/UIKit SF Symbol systemImage, RN ImageSource, Web ReactNode), background/content color, and position (position / bottomLeading).

How it lands

One resolver per platform

Each platform overlays the host overrides onto its internal token layer exactly once, at init/compose time — nothing is threaded screen-by-screen.

The text track

String & locale overrides

Copy is customized separately from colors — no dedicated "chatTitle/subtitle/hint" fields are needed because every visible string is a label key you can override.

FieldEffect
stringOverridesMap of labelKey → string; highest precedence, wins over server + built-in labels. Change the app-bar title, feed header, input hint, follow-up header, CTAs, etc.
localeForce a language code regardless of device/onboarding; also preselects the language and skips the language screen.

Put together

Examples

Android (Kotlin)

FarmerChat.initialize(this,
  FarmerChatConfig.builder(FarmerChatEnvironment.PROD)
    // Layer 3 — full brand theme
    .theme(FarmerChatTheme.builder()
      .brandPrimary(0xFF1565C0.toInt())
      .cardCornerRadius(16)
      .fontFamily(R.font.host_sans)
      .logo(R.drawable.host_logo)
      .build())
    // Layer 2 — targeted knobs
    .fabLabel("Ask AI")
    .userBubbleColor(0xFF1565C0.toInt())
    .messageFontSizeSp(15f)
    .stringOverrides(mapOf("fc_v2_app_label_app_name" to "AgriAssist"))
    .build())

Web (TypeScript)

FarmerChat.initialize({
  environment: 'prod',
  theme: { colors: { brandPrimary: '#1565C0' }, shape: { cardCornerRadius: 16 } },
  fabLabel: 'Ask AI',
  userBubbleColor: '#1565C0',
  bubbleCornerRadius: 20,
  messageFontSize: 15,
  stringOverrides: { fc_v2_app_label_app_name: 'AgriAssist' },
})
