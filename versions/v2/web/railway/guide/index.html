FarmerChat SDK Integration

FarmerChat is an AI advisory assistant for farmers — onboarding, a daily advice feed, and a chat that answers questions by voice, photo or text in the farmer's own language. This SDK embeds that whole journey inside a partner application.

The same public surface ships on seven flavours across four platforms. Every one is documented in full on this page, with the identical section list, so an integration written against one translates directly to the others.

What farmers get

FarmerChat is Digital Green's AI farming advisor. The SDK puts its chat inside your app or website, so your farmers can ask a question and get practical advice without leaving your product.

Ask by voice, photo or text

Farmers speak a question, snap a photo of a sick plant, or type. No forms, no menus.

Answers in their own language

Every word on screen comes from FarmerChat in the language the farmer picks.

Follow-up questions

Each answer suggests the next useful question, so farmers keep learning with one tap.

Listen and share

Answers can be read aloud for farmers who prefer listening, and shared with others.

Any website, no build tools

On a plain HTML page

The FarmerChat widget is one script. Paste these two tags before </body> and a chat button appears in the corner of the page; tapping it opens FarmerChat in a panel (full screen on phones).

To open chat from your own button, call FarmerChatWidget.open(), or FarmerChatWidget.open('When should I harvest paddy?') to ask straight away.

Before you go live

FarmerChat's servers do not yet accept the SDK's requests from other websites: their browser rules (CORS) block the headers the SDK sends. Until the FarmerChat team allows them, point the widget at a small proxy, as the live demo does with customBaseUrl.

The script URL below is the demo's copy. For production, host farmerchat-widget.iife.js and its illustrations/ folder on your own site or CDN.

index.html
<!-- 1. Settings (all optional) -->
<script>
  window.farmerChatWidgetSettings = {
    config: {
      environment: 'prod',
      enableAgenticChat: true,   // streaming answers
      // customBaseUrl: 'https://your-proxy.example/',
    },
    launcherLabel: 'Ask FarmerChat',
  };
</script>

Questions

Good to know

What will farmers see?

By default, only the chat: they open it and ask. Past chats and language are buttons in the chat bar. If you want the full FarmerChat journey — language and name onboarding, a Home feed of daily advice, a menu — set mode to FULL_JOURNEY.

Do answers type out as they arrive?

Yes, with enableAgenticChat on: progress steps show first, then the answer streams in word by word.

Which platforms and versions?

Android (Jetpack Compose and XML Views), iOS (SwiftUI, UIKit and Objective-C), React Native, and the web (React or a plain HTML page). Every platform is version 2.2.0.

Can we install it from Maven, CocoaPods or npm today?

Not yet. The packages are not published to public repositories, so for now you build from source and use them locally. Each platform's install section below shows how.

Platform

Android Jetpack Compose

Kotlin · minSdk 26

The Compose SDK embeds the FarmerChat journey in a modern Android app. It is the reference flavour — the screens here are direct ports of the FarmerChat app itself, so this is the closest match to what farmers already use.

Everything ships as two artifacts: farmerchat-core (networking, session, state machines, no UI) and farmerchat-android-compose (the screens). You depend on the latter; it pulls in the former.

Install the FarmerChat SDK

Before you start — read this

The SDK artifacts are not published to a public repository yet. There is no Maven Central / GitHub Packages release, no CocoaPods trunk entry, and no npm package (npm view returns 404 for both JavaScript packages). The install steps below are the shape your integration will take, and they work today against a local build.

Until a release exists, build the SDK from source and consume it locally — each platform's install section shows the local path alongside the eventual remote one.

Scope the experience

The SDK opens straight into chat by default. Switch on the full journey, or trim individual surfaces, to fit your app.

OptionWhat it controls
environmentBackend to talk to: DEV, STAGE, DEMO, PROD, EKS.
languageCodeInitial language, e.g. "en", "hi". The farmer can change it in-journey.
defaultCountryCode / defaultStateCodeSeed geography used before the farmer shares a location.
modeCHAT_ONLY (default: opens straight into chat) or FULL_JOURNEY (onboarding + home + chat).
showDrawer / showHistory / showSettings / showNameScreenTrim the journey surface by surface. showDrawer follows the mode unless you set it: off in chat-only, on in the full journey.
enableVoice / enableImages / enableWeather / enableSsfrTurn individual question modes and features off.
enableAgenticChatOpt into streaming agentic chat. Default off keeps the synchronous 1.0.0 contract.
enableAnalyticsTelemetry master switch. Default off — events are built but dropped until you opt in.
authMode + accessToken / tokenProviderSupply your own identity instead of the SDK-owned phone/OTP flow.
stringOverridesReplace any server label. Keys must be canonical fc_v2_app_label_* keys.

Chat only (the default)

Out of the box the farmer lands directly in chat, with past chats and language a tap away in the chat bar. The settings below spell that default out; pass FULL_JOURNEY as the mode for onboarding, Home and the drawer too.

Kotlin
FarmerChatConfig.Builder(FarmerChatEnvironment.PROD)
    .mode(FarmerChatMode.CHAT_ONLY)
    .showDrawer(false)    // moves history + language into the chat app bar
    .showHistory(true)    // past-advice icon
    .showSettings(false)
    .showNameScreen(false)
    .build()
Where history and language live

In chat-only mode the drawer is off by default (showDrawer follows the mode), so the past-chats and language buttons sit in the chat app bar. Set showDrawer yourself to override.

Turn off a question mode

Kotlin
FarmerChatConfig.Builder(FarmerChatEnvironment.PROD)
    .enableVoice(false)   // no mic on the composer or the home tiles
    .enableImages(false)  // no camera
    .build()

Identity and authentication

By default the SDK owns identity: farmers start as guests and can sign in with a phone number and OTP inside the journey. If your app already knows who the farmer is, supply the token instead and the SDK skips its own auth UI.

Kotlin
FarmerChatConfig.Builder(FarmerChatEnvironment.PROD)
    .authMode(FarmerChatAuthMode.HOST_TOKEN)
    .accessToken(myAuth.currentAccessToken())
    // Called at init when no accessToken was given, and again on a 401.
    .tokenProvider { myAuth.freshAccessToken() }
    .build()

After your own refresh, push the new token in without reconfiguring:

Kotlin
FarmerChat.updateTokens(access = newAccess, refresh = newRefresh)

// Session state
val signedIn = FarmerChat.isAuthenticated()
FarmerChat.logout { success -> /* … */ }

Theming

The SDK ships the FarmerChat look by default. Override the parts that must match your app — anything you leave unset keeps the FarmerChat value.

Kotlin
FarmerChatConfig.Builder(FarmerChatEnvironment.PROD)
    .theme(
        FarmerChatTheme(
            brandPrimary = 0xFF00C950.toInt(),
            cardCornerRadius = 24,
            buttonCornerRadius = 999,  // fully rounded, the current default
            inputCornerRadius = 12
        )
    )
    .messageFontSizeSp(15f)
    .bubbleCornerRadius(18)
    .build()
Buttons are pills

buttonCornerRadius defaults to 999 (a full pill) as of the 2026-09-15 design pass. Pass a smaller value to square them off.

Labels and languages

All farmer-facing text is served by the backend and resolved per language, so the journey localises itself once the farmer picks a language. To override a specific string, key it by the canonical label key.

Kotlin
FarmerChatConfig.Builder(FarmerChatEnvironment.PROD)
    .stringOverrides(
        mapOf(
            Labels.RECENT_CHATS to "Past advice",
            Labels.SHARE_LOCATION to "Share my farm"
        )
    )
    .build()
Use the generated key constants

Labels resolve as <key>_<lang> against the canonical fc_v2_app_label_* keys. A hand-typed short key silently never matches, and your override is ignored without an error. Always use the generated constants.

Analytics

The SDK emits the same events the FarmerChat app tracks, with the same names and properties, through a listener you provide. It bundles no third-party analytics SDK — forward the events to whatever you already use.

Kotlin
FarmerChatConfig.Builder(FarmerChatEnvironment.PROD)
    .enableAnalytics(true) // default false
    .onEvent { name, props -> MyAnalytics.track(name, props) }
    .onScreenView { screen -> MyAnalytics.screen(screen) }
    .onChatOpened { /* … */ }
    .onMessageSent { text -> /* … */ }
    .onAnswerReceived { messageId -> /* … */ }
    .onError { code, message -> MyLogger.warn(code, message) }
    .build()
Off by default

enableAnalytics defaults to false on every platform. Events are still constructed with their real names, properties and ordering — they are dropped at the single dispatch point, so enabling telemetry later cannot change any other behaviour.

Permissions

The SDK requests permissions at the moment a farmer uses the feature, and degrades gracefully when one is refused. You declare them; the host app owns the manifest.

AndroidManifest.xml
app/src/main/AndroidManifest.xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />

<!-- Voice questions -->
<uses-permission android:name="android.permission.RECORD_AUDIO" />
<!-- Photo questions -->
<uses-permission android:name="android.permission.CAMERA" />
<uses-feature android:name="android.hardware.camera" android:required="false" />
<!-- Weather + location-specific advice -->
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-feature android:name="android.hardware.location.gps" android:required="false" />

Only declare what you enable. If you set enableVoice(false), drop RECORD_AUDIO — a permission you never exercise still shows on your store listing.

Use the generated key constants

Labels resolve as <key>_<lang> against the canonical fc_v2_app_label_* keys. A hand-typed short key silently never matches, and your override is ignored without an error. Always use the generated constants.

Analytics

The SDK emits the same events the FarmerChat app tracks, through a listener you provide.

TypeScript
FarmerChat.initialize({
  environment: &#x27;PROD',
  enableAnalytics: true,   // default false
  onEvent: (name, props) => MyAnalytics.track(name, props),
  onScreenView: (screen) => MyAnalytics.screen(screen),
  onChatOpened: () => {},
  onMessageSent: (text) => {},
  onAnswerReceived: (messageId) => {},
  onError: (code, message) => MyLogger.warn(code, message),
});
Off by default

enableAnalytics defaults to false on every platform. Events are still constructed with their real names, properties and ordering — they are dropped at the single dispatch point, so enabling telemetry later cannot change any other behaviour.
